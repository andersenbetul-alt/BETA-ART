Beta Art Verified

Evidence before badge.

Beta Art Verified is a documented review process for photographic origin, creator identity, capture information and licensing readiness. It is not a guarantee that every possible third-party claim has been eliminated. Production records receive the badge only after the required checks are completed and retained.

01

Real capture

A real original image file is required. Prototype, synthetic and placeholder visuals cannot receive Verified Human Photograph status.

02

Creator identity

Contributor identity is reviewed by Beta Art. Contributors cannot self-verify their own identity status.

03

Capture record

Capture date, location and available camera metadata are reviewed and retained with the asset record.

04

Rights & releases

Licensing authority and relevant model/property release status are recorded before commercial availability.

05

AI disclosure

Generative changes must be disclosed. Fully synthetic images are excluded from the Verified Human Photography archive.

06

Content Credentials

Content Credentials / C2PA can be retained as an additional provenance signal when available. They do not replace rights and release review.

Required for public badgeOriginal file · identity review · metadata/capture review · location · rights review
Conditional reviewModel release · property/location permission · trademarks/artworks · sensitive context
Blocks licensingUnresolved ownership · missing required consent/release · synthetic origin · unresolved conflict
Rights-aware, not rights-blind

Recognizable people and sensitive/private contexts require documented legal-basis and consent/release assessment where applicable. A “Verified” badge describes Beta Art’s completed review record; it does not override applicable law or third-party rights.

Licensing framework · pilot draft

Clear rights before download.

Beta Art licenses defined uses rather than transferring copyright. The pilot price engine combines usage, territory, duration and exclusivity. A final production Image License Agreement must be approved by legal counsel before paid launch.

Usage

Website, social campaign, editorial and advertising are priced as separate commercial contexts.

Territory

Norway, Nordics, Europe or Worldwide.

Duration

3 months, 1 year, 3 years or perpetual.

Exclusivity

Standard, industry, territory or full exclusivity. Exclusive requests require prior-use conflict review.

Not a final legal agreement

This page is a product specification for the pilot. Copyright remains with the relevant rights holder unless expressly transferred. Final terms must define granted use, prohibited uses, sublicensing, editing, AI/ML use, credit, exclusivity, termination, liability, refunds/cancellation, governing law and conflict handling before paid launch.

Privacy framework · pilot draft

Personal data should be collected only when the workflow needs it.

The production service should document its lawful basis, purposes, retention, access controls and data-subject handling for buyer, photographer, model/release and assignment data.

Buyer data

Account, billing, license and assignment information.

Photographer data

Identity, contributor contracts, payout and verification records.

Model / release data

Release evidence should be access-controlled and separated from public image metadata.

Security

Production storage must use authenticated access, audit logs, backups and least-privilege permissions.

Legal review required

This is a privacy architecture draft, not a complete privacy notice. Production must document lawful basis, purposes, retention, access, data-subject requests, processors, international transfers, breach handling and release-record security. Non-essential analytics/marketing tracking must not start before valid consent where required.

Pilot terms

Prototype access, not commercial licensing.

This version of Beta Art is a product pilot. It does not accept payment, issue final commercial licenses or create binding photographer assignments. Final Terms of Service, Image License Agreement, Contributor Agreement and Assignment Agreement must be approved before commercial launch.

No final license

License previews are estimates/specifications only until a production agreement and payment workflow are connected.

No automatic assignment

A shoot request is an inquiry. Scope, price, cancellation, delivery and rights must be separately agreed.

No guarantee language

Beta Art Verified records completed checks; it does not eliminate every possible third-party claim.

Company information

Legal entity name, address, contact email, organization number, register and VAT status must be added before commercial launch.

AI & manipulation policy

Human capture is the starting point.

The Verified Human Photography archive is reserved for photographs that originate in a real camera capture. Editing and retouching must not misrepresent provenance, rights or material facts relevant to licensing.

Fully synthetic

Excluded from the Verified Human Photography archive.

Conventional editing

Color, crop and ordinary non-generative retouching may be accepted when provenance remains accurate.

Generative edits

Must be disclosed and reviewed. Material generative replacement may prevent Verified Human Photograph status.

Training rights

Customer and contributor agreements must state separately whether AI/ML training use is permitted; no such permission is implied by a normal image license.

Rights & consent concern

Report a possible rights issue.

Use this pilot form to flag ownership, consent, privacy, release, trademark, protected-work or other rights concerns associated with an image. In production, reported assets should be eligible for manual review and temporary licensing hold.

Pilot report recorded locally for demonstration. Production reporting must route to a monitored legal/support process.

-- BETA ART PRODUCTION DATA MODEL (DRAFT)
-- PostgreSQL-oriented reference schema embedded in the single-file pilot.
-- Production implementation still requires authentication, storage, RLS/security and provider integrations.

create table organizations (
  id uuid primary key,
  name text not null,
  country text,
  billing_email text,
  created_at timestamptz not null
);

create table users (
  id uuid primary key,
  organization_id uuid,
  role text not null check (role in ('buyer','photographer','admin')),
  email text unique not null,
  full_name text,
  created_at timestamptz not null
);

create table photographer_profiles (
  user_id uuid primary key,
  country text,
  city text,
  specialties text[],
  identity_status text not null,
  tax_reporting_status text,
  payout_status text not null
);

create table assets (
  id uuid primary key,
  photographer_id uuid not null,
  archive_id text unique not null,
  title text not null,
  description text,
  country text,
  location text,
  captured_at timestamptz,
  industry text,
  original_object_key text not null,
  preview_object_key text not null,
  status text not null,
  created_at timestamptz not null
);

create table asset_verification (
  asset_id uuid primary key,
  original_capture boolean not null default false,
  photographer_verified boolean not null default false,
  metadata_reviewed boolean not null default false,
  location_documented boolean not null default false,
  rights_reviewed boolean not null default false,
  ai_disclosure text not null,
  c2pa_status text not null,
  verified_at timestamptz,
  verified_by uuid
);

create table releases (
  id uuid primary key,
  asset_id uuid not null,
  release_type text not null check (release_type in ('model','property')),
  status text not null,
  private_object_key text,
  notes text,
  created_at timestamptz not null
);

create table lightboxes (
  id uuid primary key,
  organization_id uuid,
  owner_id uuid not null,
  name text not null,
  created_at timestamptz not null
);

create table assignments (
  id uuid primary key,
  organization_id uuid,
  buyer_id uuid not null,
  subject text not null,
  country text not null,
  location text,
  deadline date,
  budget_nok numeric(12,2),
  usage text,
  brief text,
  archive_reuse_preference text,
  status text not null,
  created_at timestamptz not null
);

create table assignment_matches (
  assignment_id uuid,
  photographer_id uuid,
  status text not null,
  quote_nok numeric(12,2),
  primary key (assignment_id, photographer_id)
);

create table licenses (
  id uuid primary key,
  organization_id uuid,
  buyer_id uuid not null,
  asset_id uuid not null,
  usage text not null,
  territory text not null,
  duration text not null,
  exclusivity text not null,
  price_nok numeric(12,2) not null,
  status text not null,
  issued_at timestamptz,
  expires_at timestamptz
);

create table payments (
  id uuid primary key,
  organization_id uuid,
  license_id uuid,
  assignment_id uuid,
  amount_nok numeric(12,2) not null,
  provider text,
  provider_reference text,
  status text not null,
  created_at timestamptz not null
);

create table rights_reports (
  id uuid primary key,
  asset_id uuid,
  reporter_email text,
  concern_type text not null,
  details text not null,
  status text not null,
  created_at timestamptz not null
);

create table audit_log (
  id bigint primary key,
  actor_id uuid,
  entity_type text not null,
  entity_id text not null,
  action text not null,
  metadata jsonb,
  created_at timestamptz not null
);
