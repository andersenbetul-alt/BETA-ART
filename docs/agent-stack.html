Agent Stack Audit

Four tools layered under Claude Code: model routing, context compression, persistent memory, and pattern capture. All four were installed and exercised. Two of them do not yet do their job — here is exactly which, and why.

Environment ephemeral Linux container, restricted egress Working 1 of 4 Partial 1 Not producing value 2

Where each layer actually sits

The stack is usually drawn as a single chain, which hides the thing that matters: only two of the four are hops in the request path. The other two never touch a request — they watch it and write back into the next session.

Running it on your own machine

Three of the four failures above are environmental, not product defects. On a normal machine with open network access, the same commands should get further.

# routing + fallback
npm install -g omniroute
omniroute                      # server on :20128
omniroute nodes add            # register a provider with your own key — the step missing here
omniroute setup-claude         # generate Claude Code profiles

# context compression — note the extras
pip install "headroom-ai[all]"
headroom proxy --port 8787

# persistent memory
npx claude-mem install
npx claude-mem start           # autostart is skipped without a TTY

# pattern capture — already in the repo
python3 .claude/skills/task-observer/scripts/observe.py list

Two things to decide

Pick one compressor

OmniRoute ships a compression pipeline and Headroom is a compression layer. Chained, they compress the same context twice — paying latency for the second pass and risking the loss of detail the first pass judged safe to keep. Run whichever measures better on your own traffic, and turn the other off.

Memory needs a clean start

Claude-Mem only records sessions that begin after it is installed, so a session that installs it will always look broken. Install it, then start a fresh session in the project you care about — and expect the first one to write, not read.
